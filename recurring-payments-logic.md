# Рекуррентные платежи — логика и спецификация

> Документ описывает поведение рекуррентных платежей в Family Finance App.  
> Стек: Expo (React Native) · Supabase · TypeScript

---

## 1. Создание рекуррентного платежа

Рекуррентность создаётся прямо из формы добавления транзакции (расход / доход).  
Чекбокс **"Рекуррентный платёж"** появляется на экране добавления транзакции.

### UI при включённом чекбоксе

```
[ ✓ ] Рекуррентный платёж

  Частота:     [ Ежемесячно ↓ ]   ← daily | weekly | monthly | yearly
  Следующий:   [ 15 мая 2026  ]   ← зависит от частоты (см. раздел 2)
  Напомнить:   [ за 3 дня    ↓ ]  ← 1 / 3 / 7 дней
```

### Что происходит при сохранении

1. Создаётся **транзакция** — текущая трата записывается в историю немедленно.
2. Создаётся **`recurring_payment`** — шаблон для будущих уведомлений, с `next_date` = дата следующего платежа.
3. Транзакция получает `recurring_id` → связь между транзакцией и шаблоном установлена.

## 2. Выбор даты следующего платежа

UI меняется в зависимости от выбранной частоты.

### Ежедневно

Дата не выбирается — `next_date` всегда завтра.

```
Следующий: завтра (автоматически)
```

### Еженедельно — выбор дня недели

```
День:  [ Пн ] [ Вт ] [ Ср ] [ Чт ] [ Пт ] [ Сб ] [ Вс ]
```

`next_date` = ближайший выбранный день недели начиная от завтра.

### Ежемесячно — выбор числа месяца

```
Число:  [ 1 ] [ 5 ] [ 10 ] [ 15 ] [ 20 ] [ 25 ] [ последний ]
```

`next_date` = выбранное число следующего месяца (или текущего, если оно ещё не наступило).

> **Edge case:** если выбрано `31`, а в месяце 28/30 дней → берём последний день месяца.

### Ежегодно — выбор дня и месяца

```
Дата:  [ 1 апреля ]  ← datepicker только день + месяц, без года
```

`next_date` = ближайшее вхождение выбранного дня/месяца.

## 3. Жизненный цикл рекуррентного платежа

```
Создан
  │
  └─► [next_date наступает] ──► Уведомление пользователю
                                        │
                          ┌─────────────┴─────────────┐
                          ▼                           ▼
                   Подтверждает                  Пропускает
                          │                           │
              Создаётся транзакция         next_date сдвигается
              next_date += 1 период        без создания транзакции
```

### Текст уведомления

```
"Аренда — 800€ через 3 дня (1 мая). Подтвердить?"
```

Тап на уведомление → bottom sheet с предзаполненной формой транзакции.  
Пользователь может скорректировать сумму перед подтверждением.

## 4. Подтверждение платежа — логика

```typescript
async function confirmRecurring(
  recurringId: string,
  actualAmount?: number
): Promise<void> {
  const recurring = await getRecurring(recurringId)

  // 1. Создаём транзакцию
  await createTransaction({
    household_id:  recurring.household_id,
    account_id:    recurring.account_id,
    category_id:   recurring.category_id,
    type:          recurring.type,
    expense_type:  recurring.expense_type,
    amount:        actualAmount ?? recurring.amount,
    currency:      recurring.currency,
    date:          recurring.next_date,
    recurring_id:  recurringId,
  })

  // 2. Сдвигаем next_date
  await updateRecurring(recurringId, {
    next_date: addPeriod(recurring.next_date, recurring.frequency),
  })
}

function addPeriod(date: Date, frequency: RecurringFrequency): Date {
  switch (frequency) {
    case 'daily':   return addDays(date, 1)
    case 'weekly':  return addWeeks(date, 1)
    case 'monthly': return addMonths(date, 1)
    case 'yearly':  return addYears(date, 1)
  }
}
```

## 6. Редактирование шаблона

При изменении шаблона показываем выбор области применения:

```
Изменить только следующий платёж
Изменить все будущие платежи
```

---

## 7. Удаление шаблона

```
"Удалить шаблон «Аренда»?"
Прошлые транзакции останутся в истории.

[ Отмена ]   [ Удалить шаблон ]
```

Транзакции с `recurring_id` не удаляются — только `recurring_payment` помечается как удалённый.

---

## 8. Связь с транзакциями

### В списке транзакций

Транзакции, созданные из шаблона, отображают плашку:

```
🔁  Рекуррентный · Netflix
```

Тап на плашку → переход на экран шаблона в разделе Recurring.

### Из Recurring в историю

На экране шаблона — список всех транзакций, связанных через `recurring_id`.

## 9. Edge Cases

| Ситуация | Поведение |
|---|---|
| Пользователь пропустил уведомление | Шаблон остаётся с просроченной `next_date`. В разделе Recurring — плашка **"Просрочен"** |
| Просрочено несколько периодов | Показываем все — пользователь подтверждает или пропускает каждый вручную |
| Сумма изменилась (аренда выросла) | При подтверждении редактирует сумму → опция **"Обновить шаблон"** |
| Удаление счёта с активными шаблонами | Попап: нужно переназначить счёт или деактивировать шаблоны |
| Выбрано 31-е число, в месяце 28/30 дней | `next_date` = последний день месяца |
| Ежегодный платёж 29 февраля | В невисокосный год → 28 февраля |

## 10. Схема данных (напоминание)

```sql
-- recurring_payments
id                  uuid PRIMARY KEY
household_id        uuid REFERENCES households(id)
account_id          uuid REFERENCES accounts(id)
category_id         uuid REFERENCES categories(id)
name                text NOT NULL
type                text NOT NULL     -- 'income' | 'expense'
expense_type        text              -- 'infrastructure' | 'operational' | 'discretionary'
amount              numeric(15,2) NOT NULL
currency            text NOT NULL
frequency           text NOT NULL     -- 'daily' | 'weekly' | 'monthly' | 'yearly'
next_date           date NOT NULL
notify_days_before  int DEFAULT 3
is_active           boolean DEFAULT true
created_at          timestamptz DEFAULT now()

-- transactions (связь)
recurring_id        uuid REFERENCES recurring_payments(id)
```
